# 训练框架分层

## 1. 总览

daisy 训练框架由两条互不依赖的链组成，在 Task 汇合：

```
Task (config + runner)
 ├─ 数据链: Dataset → Feeder → Loader
 └─ 训练链: Model → Trainer/TrainState → Plugin → Method
```

下层不感知上层。两条链之间只有一个约定：Loader 产出的 batch 结构满足 `Method.process` 与 `Method.evaluate` 的输入要求，由 Task 保证。

## 2. 数据链

### 2.1 Dataset

`daisy.dataset`

- 持有样本索引（文件路径与标签），按索引解码图像并应用 transform，返回 `图像` 或 `(图像, 标签)`；单任务标签为 `int`，多任务标签为 `dict[str, int]`；
- `DiskDataset` 是数据链的标准载体，由 feeder 产出、Task 消费；
- 提供 `subset`、`take`、`concat` 等结构操作；`dataset_split`、`dataset_sample` 是供 feeder 调用的划分与采样工具；
- 不决定数据位置、划分方式和 transform。

### 2.2 Feeder

`daisy.feeder`

- 定位样本、解析标签、划分数据，返回 `dict[str, DiskDataset]`；
- 返回的数据集 transform 为 `nn.Identity()`；
- 划分、采样、分组等可能造成泄露的逻辑全部在 feeder 中显式编写；
- 不负责 transform、类别数语义和划分是否满足任务需求，后两者由 Task 校验。

签名、注册与通用检查见 [task 规范](task%20规范.md) 4.2。

### 2.3 Loader

`daisy.util.data`、`daisy.util.transform`

- DataLoader：由 Task 构建，负责组 batch、shuffle 与多进程读取；
- Prefetcher：Trainer 在 `fit` 与 `inference` 中自动包装 DataLoader，在独立 CUDA 流上将 batch 搬运到设备，保留 pytree 结构；
- LazyNormalization：transform 以 `LazyNormalization(mean, std)` 结尾。CPU 侧保持 uint8，collate 后由 Prefetcher 在设备上转 float32 并归一化，降低 CPU 负载与传输量。同一 batch 内归一化参数一致。

## 3. 训练链

### 3.1 Model

`daisy.model`

- 纯 `nn.Module`，只定义结构与前向；
- 不含 loss、优化器与训练策略；
- Task 创建 backbone 并加载预训练权重，Method 将其组装为完整模型。

### 3.2 Trainer 与 TrainState

`daisy.training.trainer`、`daisy.training.state`

Trainer 实现固定训练循环，不含业务逻辑：

- 每个 batch 在 autocast 下调用 `process_fn(batch)` 得到标量 loss，按 `accum_iter` 缩放后反向；累积窗口结束时执行梯度裁剪、`scaler.step`、`scaler.update` 与梯度清零；
- 每个 epoch 结束写入 `train/loss`、`optim/lr`；
- `fit(loader, epochs, start_epoch=...)` 执行 `[start_epoch, epochs)` 区间；
- `inference(loader, predict_fn)` 在 eval 模式、`no_grad`、autocast 下逐 batch 调用 `predict_fn`，结果搬回 CPU 后沿第 0 维拼接，保留 pytree 结构；
- 提供 hook：`on_fit_start`、`on_fit_end`、`on_epoch_start`、`on_epoch_end`、`on_batch_start`、`on_batch_end`、`around_fit`。同一 hook 按注册顺序执行，`around_fit` 先注册者位于最外层；
- 学习率调度、评估、保存、日志、恢复均不属于 Trainer。

TrainState 是 Trainer 维护并传给所有 hook 的循环状态：

- 进度：`epoch`（零基）、`total_epochs`、`batch_idx`、`total_batches`、`global_step`（优化器更新次数）；
- `batch_loss`：当前 batch 的 loss；
- `record`：当前 epoch 的标量指标，每个 epoch 开始前清空；
- `stop_training`：置位后在当前 epoch 结束时停止训练。

### 3.3 Plugin

`daisy.training.plugins`

- 通过 `register(trainer)` 挂载 hook，实现与算法无关、可跨 Method 复用的行为；
- 状态保存在插件实例中，依赖由构造器注入；
- 插件互不引用，只通过 `state.record` 交换标量。键名格式为 `命名空间/指标`，命名空间包括 `train`、`val`、`optim`、`time`；
- 生产指标的插件先于消费者注册，如 `Eval` 先于 `BestModel`、`EarlyStop`、`CSVLog`；
- 插件可修改优化器参数组（学习率调度）或置位 `stop_training`（早停）；
- 完整训练状态（model、optimizer、scaler、epoch）的保存由插件在 `on_epoch_end` 完成。

内置插件：

| 插件 | hook | 作用 |
| --- | --- | --- |
| `CosineAnnealingLR` | `epoch_start` / `batch_start` | warmup + cosine 调度，按 `param_group['lr_scale']` 缩放 |
| `Eval` | `epoch_end` | 调用 `eval_fn(trainer)`，结果写入 `val/*` |
| `BestModel` | `epoch_end` | 按监控指标保存 `best_model.pth` |
| `EarlyStop` | `epoch_end` | 指标连续 `patience` 轮未改善时置位 `stop_training` |
| `Checkpoint` | `fit_start` / `epoch_end` | 按频率保存或滚动保留检查点 |
| `CSVLog` | `fit_start` / `epoch_end` | 将关注的指标写入 CSV |
| `Timer` | `epoch_start` / `epoch_end` | 写入 `time/epoch` |
| `EpochPrint` / `RichEpochPrint` | `epoch_end` 等 | 终端逐 epoch 输出 / Textual 训练监控 |
| `BatchPrint` | `batch_end` | 按频率打印 batch 进度 |

### 3.4 Method

`daisy.method`

Method 是定义一个算法的核心插件：

- `build_model(backbone)`：将 backbone 组装为算法所需的完整模型，加头或校验类型；
- `build_optimizer(model, lr, weight_decay)`：默认优化器，Trainer 已有 optimizer 时不覆盖；
- `process(batch) -> Tensor`：单步前向并返回标量 loss，loss 只在此计算；
- `inference_step(X)`：返回未解码的模型输出，如 logits；
- `predict_step(X)`：返回解码后的预测，如类别索引；
- `evaluate(trainer, loader) -> dict[str, float]`：通过 `trainer.inference` 推理，用 `daisy.metrics` 计算指标；多头方法使用扁平键，如 `caries/acc`；
- `register(trainer)`：向 Trainer 安装 model、optimizer 与 `process_fn`，并挂载依赖算法内部结构或状态的 hook，如 MAE 编码器冻结、MoCo 动量系数更新。

Method 与 Plugin 的边界：需要访问算法内部结构或状态的行为归 Method，与算法无关的行为归 Plugin。

## 4. Task

`daisy.task`

任务节点负责装配，不编写训练循环内的逻辑。循环内行为由 Method 或 Plugin 提供。输出目录、运行头部、快照与溯源由 runner 在调用根任务前后处理。训练任务的 `run(ctx)` 装配顺序：

1. 按配置设置 seed；
2. `feed` 取得划分，检查所需划分存在、标签在配置声明的范围内；
3. 按配置构建 transform 并设置到各划分，构建 DataLoader；
4. 创建 backbone 并加载预训练权重；
5. 实例化 Method 与 Trainer，`trainer.use(method)`；
6. 按配置挂载 Plugin，`Eval` 包装 `method.evaluate`；
7. resume：加载 model、optimizer、scaler 状态并计算 `start_epoch`；
8. `trainer.fit`。

配置模型、CLI、runtime 与 feeder 协议见 [task 规范](task%20规范.md)。
